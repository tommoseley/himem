Himem · Phone · Captured Clips · Hi-fi

An inbox for fragments.

Watch recordings sync to phone as captured clips, not memories. The app auto-opens this surface on launch when anything is waiting. The user multi-selects, then promotes a bundle into a new memory or appends to an existing one. Once organized, clips leave the inbox and live as media inside the memory they joined.

1 · Auto-open on launch · the inbox itself

Default state when the app launches with pending Watch clips. Sessions are grouped by time + location proximity (deterministic, no AI in v1). User scrolls through, taps clips to play, taps the circle to select. The Later link top-right defers to the Today banner.

Inbox · rules

  • Auto-open on launch when manifest is non-empty. Survives backgrounding via deep-link from notification, too.
  • "Later" exits to Today — the banner persists there as the return path.
  • Group by capture session: clips within ~10 min and ~50 m of each other.
  • Source icon per clip: today, only Watch. Future: Siri, AirPods, Phone-quick.
  • Failed-transcript clips render with "No speech detected" so the user can delete with confidence.
  • Selection persists across groups — the action bar tracks the total.

Principles for review

Settled in this design

  • The Watch captures fragments; the phone turns fragments into memories. Inbox is the seam.
  • Auto-open on launch when the inbox is non-empty. The user sees their work first.
  • Group by capture session, deterministic on time + location. No AI in the grouping itself; AI helps with the title only.
  • Suggestion, not magic. AI tags everything it pre-fills; touching the field makes it user-authored.
  • Single canonical name: "Captured Clips" everywhere, with "X new from Apple Watch" only as banner copy.

Open questions

  • What happens to Today during auto-open? Does the inbox replace Today on launch, or layer over it as a sheet? My instinct: full screen with a Later/Done button, not a sheet — this is the user’s primary task right now.
  • Group splitting. Can the user split a captured-session group into two before promoting? Probably v1.5; for v1, multi-select is enough.
  • "AI suggestion off" setting. Should there be one? Some users will prefer to author titles from a blank field every time.
  • Reminder extraction. The original spec mentioned AI-detected next-steps becoming reminders. v1.5 polish — not on the create-memory sheet.
