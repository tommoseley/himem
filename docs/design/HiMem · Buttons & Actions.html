Crucible · interaction standard

Buttons & Actions

One look per job, so the user never has to guess what is tappable or what it will do. The button colour says who acts: ochre = you (commit, save, keep), blue = the AI (organize, reorganize, run, review a draft). Destruction is red, in a swipe only. Three meanings, learned once.

The colour code — three meanings, learned once

A user should be able to internalize this in a day and never think about it again.

Ochre · you act — commit, save, keep
Blue · the AI acts (button), or an inline link / AI signal
Red · destruction (the bottom Delete button)

1 · Buttons — ochre = you, blue = the AI

Every real button is ochre (you act) or blue (the AI acts). Rank is carried by fill and width within each colour. One primary per surface; it is the loudest interactive thing on screen. The AI sparkle rides on blue buttons and is dropped from ochre ones.

Rank 1
Primary · the loudest action
Filled, full-width, one per surface. Ochre when you commit (Keep this version); blue when it invokes AI (Organize with AI). ≥50px.
Rank 2
Secondary · the alternative
Hairline border, no fill, full-width. Sits directly under the primary. Same size, quieter weight.
Rank 3
Tertiary · inline action
Bordered pill inline in a row — blue because Reorganize and Run invoke AI. Filled only when it is the sole action of its card. ≥44px.
Labelling · blue buttons
Name the AI, don't just hint it
A blue button carries a verb that names the AI (the promise) + a trailing sparkle (the marker) — Organize with AI ✦, Reorganize with AI ✦, Analyze with AI ✦, or a named feature (Find the thread ✦). The sparkle sits after the label. Two signals, one honest meaning: the user always knows when they're handing work to the AI. The sparkle is mandatory; the “…with AI” phrasing is used wherever it reads naturally. Never ghost it cream-on-cream — honesty shouldn't cost the button its presence; it stays a legible blue.

2 · Inline links — blue

Tappable text that opens, reviews, or edits in place. No border, no pill — it reads as a link, never competing with a real button.

Review & navigate
Blue, ≥44px tap target. Used for Review ›, Retry transcription, and edit links. If it needs more weight than a link, it should become a tertiary button, not a louder link.
Add / incomplete
Dashed affordance
+ Edit+ New
Dashed = add or provisional, only. Topic editing, a new-topic stub. Never used for status or for a committed action.

3 · Destructive — the bottom Delete button

Destruction is a full-width Delete button at the bottom of an opened item, below all its content. To reach it you open the item and scroll past everything — that scroll is the deliberation, so there is no confirm dialog. Swipe-to-delete is retired everywhere (June 12 2026): you can't destroy what you haven't deliberately opened and scrolled through. Recently Deleted (30 days) is the safety net.

Removes a memory from a project — the memory itself is untouched, returned to the pool. Same bottom-button shape, parallel red, label carries the difference.
Rule
One affordance, one place
No swipe-to-delete, no floating circle, no toolbar trash, no list-row destroy. Every destroy/remove is the bottom Delete button inside the opened object. Open → scroll → Delete is the entire deletion vocabulary, identical for memories, clips, and projects. (Origin: accidental swipe-deletions — the deliberate open-and-scroll gesture is hard to do by mistake.)

Do / Don't

Do

  • Ochre primary = you commit; blue primary = invoke AI. One per surface.
  • Blue for AI buttons, inline links, and AI status signals — form keeps them distinct.
  • Red is the bottom Delete button only — open the item, scroll, Delete.
  • Bare text actions confined to the nav top bar.

Don't

  • Colour a button against the rule — ochre is you, blue is the AI.
  • Dress status (Draft organized) as a dashed button.
  • Swipe-to-delete, floating circles, or a toolbar trash for destroy/remove.
  • Make a real action a bare blue text link in the page body.
