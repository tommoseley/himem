Where it breaks — confirmed

  • One tap → two present() calls from the same NavigationStackHostingController, though sheetContent fired only once. SwiftUI’s internal machinery double-fired.
  • Present #1 (Z) succeeds and becomes the blocker for present #2 (X). Both are ours — same .fullScreenCover(item: $activeSheet). We are Z.
  • The loose thread is the stray dismiss() between the two presents. Find who calls it and the double-fire’s source is named.

Fix paths

  • A — backtrace the dismiss (do first, ~5 min). Symbolicate who calls dismiss() on the nav host between the presents. If it’s our code (a reactive @Environment(\.dismiss), a binding in BottomDelete / back / onRemoveFromProject) → suppress it and the second present never happens.
  • B — manual present (robust fallback, ~10 min). Present UIHostingController(DraftReviewSheet) once, ourselves; sync dismissal back to activeSheet. Exactly one present call, no SwiftUI double-fire. Keep swipe-down via the presentation controller (§8.0 needs it).
  • C — lift owner to EntryExpandedView (last). Speculative: if the cause is identity churn / a reactive dismiss, moving the owner may not help. Don’t lead with it.
