Where a memory was made.

We capture location at the moment a memory is composed (currently 18 Columbus Cir, Bluffton). The question is where that fact lives in the UI — specifically on the maximal home card and the memory detail screen. This doc explores three treatments per surface, and lands on a recommendation. Both surfaces should show location, but the role and weight differ.

Home · Maximal card

On the home feed, location is metadata — a recognition aid alongside time and composition. It should be glanceable, never compete with the memory’s content. Three options:

Recommendation

Show location on both surfaces — with different weight.

On the home card, location is metadata; on detail it’s a tappable affordance. Same data, different role.

  • Home card — pick B. Inline metadata, pin glyph (not navigation arrow), place name preferred over street.
  • Detail screen — pick E. Pin chip below the date row, tappable, with chevron.
  • Glyph rule: use mappin for “memory was made here”. Reserve location.north.fill for live tracking only.
  • Truncation rule: place name › locality+street › locality. Never trailing comma+ellipsis.

Open questions

  • Privacy: Settings toggle “Save location with new memories” — default on, with a per-memory edit affordance in the menu.
  • Reverse geocoding: we need MapKit’s CLPlacemark for place-name resolution. Cache results — geocoding rate-limits aggressively.
  • Search/filter: once location is first-class, “memories near here” should appear in Search’s zero state alongside Recent and Saved.
  • Tap action on detail: open in Apple Maps, or open an in-app “all memories from here” list? Default to Maps for v1.
Each of these wants its own design pass — flagging for the v1 audit.
