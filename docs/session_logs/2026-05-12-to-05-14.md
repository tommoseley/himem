## 05-12 — iPhone consolidation fix, List swap, photo grid (commit 5b862cf)

### Append per-capture fragments
- `EntryLifecycleService.append` no longer concatenates typed text into `entry.content`. Each typed append now mints its own `.note` MediaReference; orphan `entry.content` text gets promoted to a `.note` anchored at `entry.createdAt` before the new fragment is added so the regenerate step doesn't drop it.

Catches the multi-voice case where the joined transcripts equal `entry.content` and the old `any-.note?` guard wasn't enough. ## 05-13 — Watch design rebuild (Capture + Pages)

### Watch Capture refinements
- Pulsing ring on recording disc replaced with a live mic-level meter. `AVAudioRecorder.isMeteringEnabled = true`, tick cadence 500ms → 100ms, `averagePower(forChannel:)` → `audioLevel: CGFloat` via -55/-5 dB perceptual map. Ring scale + opacity react in real time.
- Cancel demoted: bespoke `WatchPageHeader`-corner `xmark` chip initially placed top-leading, then per design-system spec moved next to **Stop & save** as a small 38pt round secondary (capsule background, hairline stroke). "Discard recording?" confirm sheet retained for non-trivial recordings.
- Bottom row gets `padding(.horizontal, 14)` + `padding(.bottom, 14)` on outer VStack to lift buttons off the watch case's rounded-corner curve (Ultra hardware clips otherwise).

### Watch · Pages (swipe model)
- `WatchHomeView` is now a `TabView(.page)` with three tags: `LATEST` (replay newest pending clip), `CAPTURE` (default landing — the mic), `PENDING` (queue).
- Watch always lands on the center page. Recording state replaces the TabView via the existing `coordinator.route` switch in `WatchRootView` — page dots vanish, swipe disabled, `Stop & save` / ✕ are the only exits.
- Page dots provided by `.tabViewStyle(.page)`. The "Tap to view" pending footer retired.
- New `WatchLatestPage` (was a stub). Reads `WatchPendingManifest.shared.clips.first`; renders duration + relative date label, 22-bar `WaveformBars` glyph (ochre up to playback progress, dimmed white after), `0:18 / 0:39` time markers, 44pt circular play/pause button. `LatestPlaybackService` is an `AVAudioPlayer`-backed `ObservableObject` with a 4Hz ticker; deactivates `AVAudioSession` on stop / page disappear. Falls back to "No recent memory" placeholder when nothing pending.
- `WatchPageHeader(pageTitle:)` shared across all three pages: `HIMEM · <PAGE>`. After several positioning iterations (per-page `safeAreaInset`, then per-page header child, then header above the TabView with `.ignoresSafeArea(.container, edges: .top)`), final position is via a single outer-VStack header above the TabView; baseline aligns with the system clock band via explicit `padding(.top, 24)`.
- `WatchPendingListView` gets an `embedded: Bool` flag — true when inside the home TabView, the inline chevron is suppressed in favour of the parent's shared header.

### Pending list — native swipe + density
- `LazyVStack` → `List` so `.swipeActions(edge: .trailing, allowsFullSwipe: true)` actually works on watchOS (`LazyVStack` rows silently ignore the modifier). `.listStyle(.plain)`, `listRowBackground(.clear)`, `listRowInsets(EdgeInsets(top: 3, leading: 8, bottom: 3, trailing: 8))`. `listRowSeparator(.hidden)` was discovered to be unavailable on watchOS; OLED background makes separators invisible anyway.
- Row redesign: vertical padding 8 → 14pt, horizontal 10 → 12pt, font 10.5/11 → 11/12pt, clip shape `RoundedRectangle(cornerRadius: 14)` → `Capsule()`. "Saved on watch" subline removed (the section header conveys it).
- "All caught up" check sized 36/18 → 28/14pt with `.transition(.scale(scale: 0.6).combined(with: .opacity))` so the empty-state arrives with a small flourish.

### Sync flash
- `WatchPendingManifest.remove(clipId:viaSync:)` defaults to `viaSync: true`. When true: clipId added to `syncingClipIds`, row holds for 1s with a green `✓ Synced` badge + green dot, then `performRemoval` runs (audio file deleted, row removed). User-initiated swipe-delete uses `viaSync: false` — no badge, immediate removal.
- `WatchAppCoordinator`'s ack-subscriber calls `remove(clipId:)` with default `viaSync: true`, so iPhone-confirmed clips get the flash and user-driven deletes don't.

### Watch-side flush request
- Pull-to-refresh on `JournalView` now also calls `WatchSessionDelegate.shared.requestWatchPendingFlush()`. Sends `["command": "flushPending"]` via `sendMessage` when the watch is reachable. Watch's `WatchTransferService` recognises the command and re-queues every clip in `WatchPendingManifest.shared.clips` via `transfer.send(clip:)` (system de-dupes in-flight transfers).
- No `transferUserInfo` fallback — by the time the watch is reachable to receive the queued user info, the system's automatic retry has already fired.

### Haptics
- `WatchRecordingService` plays a haptic on start (`.start`), stop-and-save (`.stop`), and discard (`.failure`). After user feedback that the patterns were too long / too loud, switched all three to `.click` — the briefest / quietest haptic watchOS exposes (Digital Crown detent pattern). No API exists to mute the click audio without disabling haptics entirely.

### Silent-audio discard
- `WatchRecordingService` publishes `peakAudioLevel: CGFloat` — running max of `audioLevel` over the recording, reset on every `start()` / cleanup.
- `WatchRecordingView`'s ✕ button now skips the "Discard recording?" alert when **either** `elapsed < 1.0` (quick-tap) **or** `peakAudioLevel < 0.1` (~ -50 dB, below typical room tone). A 30-second silent recording goes away with no confirm; anything that captured real audio still confirms.

## 05-13 — Bidirectional ack hardening

### Drop `isReachable` guard
- iPhone's `sendConfirmation` no longer gates `sendMessage` on `session.isReachable`. The iPhone's view of reachability is stale when it's been briefly woken by WC to handle `didReceive(file:)`. `sendMessage` is now attempted unconditionally; its error handler logs and the durable `transferUserInfo` backup still queues either way.

### Foreground reconciliation
- New `WatchSessionDelegate.reconcileWatchAcks()` walks `InboxManifest.shared.clips` and re-sends `sendConfirmation` for every clip. Wired to `.onChange(of: scenePhase)` in `MemoryStreamApp` — every time the iPhone app becomes active, every clip the iPhone holds gets a fresh ack pushed to the watch. Watch's `pending.remove` is idempotent, so re-asserted acks for already-removed clips are no-ops.

### Reachability change handlers — confirmed absent
- Verified neither the watch's `WatchTransferService` nor the iPhone's `WatchSessionDelegate` implements `sessionReachabilityDidChange(_:)`. The all-day BT in/out churn doesn't trigger any code we wrote — battery-drain investigation ruled out reachability as a vector.

## Risks
- TabView `.page` style on watchOS centers per-page content vertically; one-shot header `safeAreaInset` per page produced inconsistent baselines. Solved by hoisting the header above the TabView entirely. If watchOS evolves the TabView page layout in a future update, the header position may drift.
- `LatestPlaybackService` deactivates `AVAudioSession` on `stop()` (called from page disappear + `audioPlayerDidFinishPlaying`). If the watch app is killed by the system while audio is mid-playback, the session may stay active until next launch. Cleanup belt-and-braces would be `.onDisappear` plus a scene-phase observer on the watch.
- Notification-coordinator state (last push timestamp, current burst window, last review timestamp, stale-scheduled timers) will be persisted in `UserDefaults` — no migration plan defined yet for users who upgrade across the change.
