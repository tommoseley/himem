## The work

### F25 · The Projects FAB created nothing (`dcef537`)

**Root cause: the landing decision was taken at *completion*, from live navigation state the capture flow itself destroys.** `ProjectDetailView` clears its id on disappear; the capture host lives at the tab shell *above* the Projects `NavigationStack`; photo/video present as `fullScreenCover`, which removes the covered view and fires its `.onDisappear`. `route(tab: .projects, projectContext: nil)` → `.openNewProjectSheet` → a bare **`break`**. The item was dropped on the floor.

`CaptureLandingRouter` was **correct throughout** — a test of the router alone stays green through the entire defect.

**Fix: decide at tap time** (`beginCapture`), which also makes the fix independent of *which* presentation style clears what — so it covers attach, photo and video together. Chasing iOS 26 `.sheet`/`onDisappear` semantics would have fixed one path and left two. The evidence the context is present at tap is **the FAB variant that rendered**: the in-project modality stack only draws under `.createMemoryInProject`.

### F26 · The walkthrough was an open-loop machine (`8170289`)

**Six reported symptoms, one cause with three properties — and two symptoms are the same defect.**

- **A ·** The script assumes the **Clips** pipeline. `clipDidLand()` has one caller, gated on `pendingReturnToClips`, which only the `.dropOnBench` branch sets. On Memories the flag never flips. **Cold launch lands on Memories** — the default first-run user began on the one tab where step 2 could never arrive.
- **B ·** No anchoring (F16, unchanged). *"Tap View"* names a control that **does** exist and **is** held open for the walkthrough — nothing connects a top banner to a bottom toast. The button was never missing; **the pointing was.**
- **C ·** No terminal state. `advance()` is a no-op for every pipeline beat, and `finish()` is the only thing clearing `walkthroughMemoryId`, which the ring reads through `isRunning`.

> **"Step 5 never appears" and "the ring persists after completion" are ONE defect.** There is no after-completion. It never terminated; the stuck ring is the visible residue. That is Judi's *"you abandoned me after step one"* expressed structurally.

**A leak the tests found inside the fix:** `finish()` did not clear the new `pendingClipsTabSwitch`, so an unconsumed tab request could survive termination and yank the user to Clips later — the same class (state outliving the machine) reproducing inside its own fix. Second such echo this week after `:614`.

### F27 · Breadcrumbs named a place, not the control (`144079d`)

**Verify-first prevented the wrong fix.** Reported as *"there is only 'Show me around'"* — but **`Settings → Learn` exists and works** (live `NavigationLink` → `TutorialsHubView`, title "Learn"). Deleting it as a false promise would have been the `summaryUserEdited` mistake exactly. It failed two other ways: it stopped at the door (the row is **"Show me around"**), and it named the longer of two routes (a `?` sits in the toolbar of the screen she is already on).

**The durable half is the binding:** the copy is asserted against `TutorialCatalog.tour.title`, not a literal — rename the row without moving the copy and it fails in the suite, not on a user's screen.

**An existing copy test went red and was treated as a question:** `doneBeat_closingLineKeepsBothPromises` pinned the literal `"Settings → Learn"` under the message *"names the re-run path."* Promise intact, phrasing moved → the assertion was rewritten to pin the promise. First real encounter for the F16 governance rule.

### F29 · The hit-region guard could not see a filled String-label button (`d236f09`)

`Button("Got it", action:)` takes a **String label** — no label closure, so a fill decorates the *Button*, not its label: the pill draws, the taps don't. **`filled` was the original predicate's exoneration**, which is why it scored clean forever; for a String-label button a fill is evidence *of* the defect.

**Validated candidates, did not trust the count: 11 flagged → 2 genuine.** The other 9 were a fixed 32-line window bleeding into an enclosing container's `.background`. Same over-report as F17 (16 → 7). Predicate now attributes decoration to the button's **own** modifier chain, with a regression test.

The two real sites: `SectionHelp:296` ("Got it"), and **`WalkthroughOverlay:181` — "Start", the walkthrough's own entry button**, full-width ochre and tappable only on the word.
