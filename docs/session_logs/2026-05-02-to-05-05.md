## 05-05 — Audio player, per-clip transcript schema, TextSegment schema, chronological view, swipe-to-delete

### Audio player
- `MediaTile` audio rendering grew an optional `createdAt` parameter — when provided, footer shows `h:mm a · m:ss` (capture timestamp · duration). Duration loaded async via `AVURLAsset`.
- New `AudioPlayerSheet` — header with timestamp + duration, scrub bar, play/pause button, transcript area. `AudioPlayerService.currentAVPlayer` exposed (read-only) for scrub-bar polling.
- `EntryExpandedView` voice tap → presents sheet (legacy `audioFilePath` and per-MediaReference voice tiles both wired).

### Per-clip transcript on `MediaReference`
- New optional `transcript: String?` attribute on `MediaReference`.
- `EntryLifecycleService.createMediaReference(forEntryId:localIdentifier:mediaType:transcript:)` — sets and saves the transcript when provided.
- `ContributeSessionViewModel.persistVoiceCapture` passes the trimmed transcript through.
- `MediaDisplayItem.transcript` populated by mapper.
- `AudioPlayerTarget` carries the per-clip transcript so the sheet prefers it over the entry-level fallback.
- **CloudKit deploy required** before next TestFlight.

### `TextSegment` schema (Phase 1 of chronological captures)
- New entity `TextSegment(id, text, createdAt, entry)`.
- `JournalEntry.textSegments` inverse to-many relationship, deletionRule cascade.
- `JournalEntry.textSegmentsArray` sorted-by-createdAt accessor.
- `StorageService.createTextSegment` factory.
- **CloudKit deploy required** before next TestFlight.

### Phase 2 — typed notes persist as TextSegments
- `ContributeSessionViewModel.SessionTypedNote(id, text, createdAt)` replaces `[String]` tracking.
- `trackTypedNote` calls `EntryLifecycleService.createTextSegment` immediately.
- `performDiscard` deletes both MediaReferences and TextSegments by id; for existing-memory anchors it also calls `regenerateContent`.
- `EntryLifecycleService.finalizeContribution` now derives `entry.content` from `joinedContent(from:)` — sorted segments + voice transcripts in `createdAt` order.
- `regenerateContent(forEntryId:)` exposed for other paths.
- `updateTextSegment(id:text:entryId:)` and `updateMediaTranscript(mediaId:transcript:entryId:)` for inline edit.
- AI continues to read `entry.content` unchanged.

### Phase 3 — `ChronologicalCaptureStream` view
- Three panel kinds rendered in `createdAt` order:
  - **Voice clip**: speaker icon + transcript text. Tap speaker → AudioPlayerSheet. Double-tap transcript → inline edit.
  - **Note**: text. Double-tap → inline edit.
  - **Photo filmstrip**: contiguous image/video MediaReferences group into one horizontal-scroll panel.
- Photo grouping rule: walk captures sorted by createdAt, accumulate consecutive image/video items, flush whenever a voice or note breaks the run.
- `EntryDisplayModel.textSegments` + `MediaDisplayItem.createdAt` added.
- `EntryExpandedView` routes per-panel actions through a direct `EntryLifecycleService` instance (deletes + edits write through and call `regenerateContent`).
- `isLegacyEntry` = `textSegments.isEmpty && mediaItems.isEmpty` — legacy entries keep the old single-block + media-grid layout. No migration: an entry flips when its first capture lands.

### Action Box chronological order
- `SessionCapture` and `SessionTypedNote` gained `createdAt`.
- Tile area walks a unified item list sorted by `createdAt`; live recording card pinned at the bottom.
- `ScrollViewReader` auto-scrolls to the live card on `isRecording` transitions and capture-count changes.

### Swipe actions (pill-style, both directions)
- Voice + note panels: × removed, replaced with custom `swipeActions` modifier (Outlook-style).
- **Right-to-left drag** → trailing red Delete pill (standard iOS direction).
- **Left-to-right drag** → leading blue Edit pill — fires `onEdit` callback.
- Drag past 200pt and release commits in one motion; partial reveal lets you tap the pill to confirm.
- Pills are inset from the row edges (4pt all sides, 14pt corner radius) so they read as separate buttons.
- `simultaneousGesture` so parent ScrollView's vertical scroll still works.
- Direction-lock state: once `|dx| > 4` with `|dx| > |dy| × 1.4`, lock into swipe mode for the rest of the gesture.
- When `onEdit` is nil, rightward drags clamp to 0 so panels that only support delete can't reveal an empty pill.
- Tapping a pill snaps offset back to 0 (animated) before firing the action — prevents the pill from stretching when the panel switches to a taller editing layout.
- Photo filmstrip tiles keep their inline × (horizontal scroll competes with the swipe gesture).

### Voice clip flow: sheet is the canonical play + edit surface
- Voice panel reduced to pure transcript text — speaker icon and inline edit removed.
- Tap on the voice panel does **nothing**. The AudioPlayerSheet is reached only via the Edit-pill swipe (per user spec).
- AudioPlayerSheet's transcript area becomes a TextEditor (always editable).
- Sheet toolbar gains **Cancel** (leading, discards changes) alongside **Done** (trailing, saves if changed).
- New `onSaveTranscript` callback wired through `AudioPlayerTarget.mediaId` → `lifecycle.updateMediaTranscript`. Legacy voice refs (no mediaId) display the entry.content fallback as read-only because their text lives in entry.content's edit path.
- `ChronologicalCaptureStream` API simplified: `onPlayVoice` and `onEditTranscript` callbacks collapsed into a single `onOpenVoice`.

## Risks

- Legacy entries (no `textSegments`, no `mediaItems`) keep rendering with the old single-content-block + media grid. Mixed entries that have media but no segments **will** now use the chronological view; voice clips without per-clip transcripts will show "(no transcript)".
- Per-clip transcript and TextSegment outbound sync silently fails until CloudKit Production is deployed.

Search and AI both still read `entry.content`, so they continue to work — but any direct `entry.content =` writes outside `EntryLifecycleService` are at risk of being overwritten on next regenerate.
