## 2026-06-18 — Cold-launch transcription race + AirPods + Troika review

### Cold-launch transcription race + AirPods (`4c0e86f`)
**Bug:** 2 watch on-a-roll clips stuck on "Transcribing…" 20+ min after iPhone launch.

**Root cause:** `MemoryStreamApp` only observed `scenePhase` for the transcription backstop. On cold launch SwiftUI fires `.onChange(of: scenePhase)` with `.active` BEFORE `LaunchScreenView`'s async storage init flips `storageReady = true`. Handler exits at `guard storageReady`; no second observer covers the gap.

**Fixes:**
- `MemoryStreamApp.swift` adds `.onChange(of: storageReady)` that calls `transcribePendingInboxClips(trigger: "scene-active")` when storage transitions ready.
- `WatchSessionDelegate.transcribePendingInboxClips` gains a `scheduleRetryIfStillPending` helper: 30s self-cancelling retry timer for non-`.transcribed` outcomes. Idempotent (cancels prior retry on re-arm). Stops when queue drains.
- `transcribePendingInboxClips` gains a `trigger:` parameter so logs distinguish arrival / scene-active / retry entry paths.
- Diagnostic logs (`[LifeDx]` + `[InboxDx]`) added across lifecycle + dispatcher.
- `SpeechService.swift` audio session category options gain `.allowBluetoothHFP` so iPhone routes voice input to AirPods/Bluetooth mics when connected.
- Money tests in new `MemoryStreamTests/ColdLaunchTranscriptionRaceTests.swift`: `deferredOutcome_armsRetry_andLeavesClipPending`, `multipleSweeps_doNotStackRetries`, `emptyQueue_doesNotArmRetry`. First two verified ❌→✅ with fix removed/restored. Suite serialized per CLAUDE.md test-concurrency rule.

## Risks
- The cold-launch storageReady bridge runs the inbox-transcription sweep without scene-active gating. If `storageReady` ever flips true while the app is `.background` (push-driven launch?), the dispatcher runs in background — should be safe because it only reads/writes manifest + calls SpeechAnalyzer, but worth watching in TF logs.
- WCSessionUserInfoTransfer backup for pre-announce adds queue pressure on the iPhone's per-session userInfo queue. iOS limits are documented but not encoded as a hard cap on our side — a burst of acks plus burst of pre-announces could in theory hit Apple's queue ceiling. Unlikely in normal use; flagged for observation.
- `WKExtendedRuntimeSession` with `.mindfulness` reason works today but is legacy/deprecated in some App Store contexts. If Apple ever forces a different reason, recordings beyond ~15s of screen-off could regress.
- Orphan rescue path synthesizes manifest rows from filenames — fine for watch-recorded master files (filename IS clipId), but if anything else writes `.caf` to `audioDirectory` with a UUID-string filename, rescue would mis-identify it as a manifest row.
- Decode-failure rescue loses metadata (lat/long, rollGroup, nextTapOffsets). Rescued clips deliver to iPhone as standalone recordings — split rolls degrade to N independent clips instead of one session. Acceptable degradation for a rare path.
