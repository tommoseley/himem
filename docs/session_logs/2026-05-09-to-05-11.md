### SpeechAnalyzer migration (Live + file paths)
- `SpeechService.swift` rewritten on iOS-26 `SpeechAnalyzer` + `SpeechTranscriber`.
- Architecture matches Itsuki's reference (github.com/0Itsuki0/SwiftUI_SpeechAnalyzerDemo): persistent analyzer/transcriber across recordings, single long-running `transcriber.results` consumer Task, per-recording AsyncStream input, AVAudioConverter bridge.
- Four hidden iOS-26 API contracts discovered + documented in source:
  1. Buffers must be Int16 PCM (Float32 trips precondition crash).
  2. Buffers must be at 16 kHz (model rejects engine's native 48 kHz: `SFSpeechErrorDomain Code=4`).
  3. `analyzer.prepareToAnalyze(in:)` MUST be called before `start(inputSequence:)`.
  4. Use `start(inputSequence:)` for live (not `analyzeSequence(_:)`) — `analyzeSequence` cancelled mid-stream in our setup.
- Use `SpeechAnalyzer.bestAvailableAudioFormat(compatibleWith:)` instead of hardcoded format.
- `SpeechAnalyzer.Options(modelRetention: .processLifetime)` so model stays loaded between recordings.
- `SpeechTranscriber.Preset.timeIndexedProgressiveTranscription` for live (volatile + final result distinction).
- 120-second test fixture generated via `say + afconvert` → `MemoryStreamTests/Fixtures/long-speech-90s.caf`.
- Money test `TranscriptionServiceLongFormTests.transcribe_longClip_coversBeyondSFSpeechRecognizerCeiling()` asserts coverage > 60s.

### Typed-note text invisible bug (commits 466a8ca + d250b68)
- Symptom: created memory with typed note, added photo. Feed showed the text (reads `entry.content` directly via `EntryCardView`); detail view showed only the photo.
- Root cause: `handleCapturedItemForNewEntry case .note` wrote `entry.content` only — no `.note` MediaReference. Once mediaItems became non-empty (photo append), `ChronologicalCaptureStream` walked mediaItems and rendered nothing for the bare `entry.content`.
- Write-time fix: typed-note path now also calls `viewModel.createNoteFragment(forEntryId:text:)` after saveEntry.
- Read-time fix: `EntryExpandedView.onAppear` runs `migrateOrphanedContentIfNeeded()` — detects orphaned `entry.content` (no `.note` covers it, no voice transcript matches) and auto-converts via `lifecycle.createNoteFragment(forEntryId:text:createdAt:)` using `entry.createdAt` so the migrated note lands first in chronological order.
- `EntryLifecycleService.createNoteFragment` extended with `createdAt:` parameter (defaults to `Date()` for fresh captures).

## 05-11 — Notifications + watch ack

### Watch-clip notification toggle removed (commit 1481995, part 1)
- Dropped the per-feature "Notify when watch clips arrive" Toggle from SettingsView. The default-OFF toggle gated `notifyInboxArrival()` so clips landed silently unless the user enabled the switch.
- Removed `NotificationService.Keys.notifyInboxArrival`, the `registerDefaults` entry, the `@AppStorage` binding in SettingsView, and the guard at the top of `notifyInboxArrival()`.
- Watch-clip arrival is now first-class — fires whenever the iOS-level notification permission is granted. Daily Nudge stays opt-in.

### Dual-path watch ack (commit 1481995, part 2)
- Symptom: clip migrated successfully to phone, but watch complication kept showing `pendingCount = 1` for an indeterminate time.
- Root cause: `WatchSessionDelegate.sendConfirmation` used `transferUserInfo` only — durable but iOS delays delivery to "when appropriate," typically seconds to minutes when the watch app isn't actively running. Watch's pending manifest couldn't clear → `WatchSharedState.pendingCount` stayed stale → complication's widget timeline stayed stale.
- Fix: dual-path. Fire `sendMessage` first when `WCSession.default.isReachable` (instant delivery), always also queue `transferUserInfo` as durable backup.
- `handleAckPayload` is idempotent (sets `@Published lastAckedClipId` — same-value sets don't re-fire Combine sink), so receiving the ack via both paths is harmless.

### Notification permission UX (commit 4a988d0)
- Symptom: existing users stuck at `.notDetermined` had no UI path to grant notifications — onboarding's permission flow only fires for new installs.
- Fix 1 (auto-prompt): scene-active handler now calls `NotificationService.requestPermissionIfNeeded()` every activation. Idempotent — iOS only shows system dialog when status is `.notDetermined`, no-ops otherwise.
- Fix 2 (Settings status row): new state-aware row at top of Notifications section:
  - `.notDetermined` → "Allow Notifications" button → fires system prompt.
  - `.denied` → "Notifications Off — Open Settings" button → deep-links to iOS Settings.
  - `.authorized` / `.provisional` / `.ephemeral` → "On" label, no action.
- Footer copy updated per permission state.

### Other fixes
- `MemoryStreamApp.retryPendingInboxTranscriptions()` — scene-active sweep that retries `transcribeAsync` for inbox clips with `transcript.isEmpty && !transcriptionAttempted`. Covers the case where the background WatchConnectivity wake-up received a clip but iOS suspended the app before transcription completed.
