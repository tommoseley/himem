## Toolchain and environment — two decisions the next person must not casually reverse

### 1 · The phone gate is PINNED to an iOS 26.4 runtime. Do not rotate onto 26.5.

Simulator attrition forces rotation, and the tempting fix is "grab any available iPhone." **Do not take a 26.5 device.** The known-8 `SpeechAssetGate` failures exist *because* the en_US speech asset is unsupported on this 26.4 runtime. A 26.5 runtime may ship or resolve that asset differently, which would **silently move the failure count** — and the gate's entire readability depends on "8, and the same 8." A run that comes back with 5 failures or 0 is not good news; it is an **incomparable measurement** that destroys the baseline and looks like a fix.

Same family as every other trap in Measurement Discipline: a well-formed number that quietly changed meaning. If a 26.4 device is genuinely unavailable, **erase and recreate a 26.4 device rather than moving runtime**, and if the runtime must move, re-cut the baseline explicitly and say so — never let it drift inside a routine rotation.

## F24 — four defects on one surface, four commits

Reported as "editing the transcript bounced and left the text unchanged; Transcribe again bounced without firing." Root-caused to **four independent defects**, three of which alone reproduce the report.

| # | Defect | Commit |
|---|---|---|
| 1 | Top-bar `Done` discarded the edit it claimed to commit | `0482cd3` |
| 3 | An edit that reached no store reported success | `2988de7` |
| 2 | A successful bench edit still displayed the pre-edit text | `8dc03a1` |
| 4 | A transcription that heard nothing said nothing | `ee4d9d9` |

- **D1** — `commitOpenEdits` nil'd the drafts under a comment asserting *"the ClipEditor coordinator commits."* It does not: closing fires only `coordinator.end(id:)` → `activeEditId = nil` → `switchedToOtherEditor == false` → `.stayEditing`. A phantom comment directly on top of silent data loss, on the natural gesture.
- **D3** — three writers each ended a miss in a bare `return`, and `writeBenchClipTranscript` stacked two. A clip in neither store lost the edit silently. Writers now return the stored text or nil.
- **D2** — `Source.inbox` wraps `InboxClip`, a **struct**: a frozen snapshot captured at `.sheet(item:)` presentation, never re-read. A correct save rendered the pre-edit text. `.managed` was never affected (`NSManagedObject` is a live read).
- **D4** — `userFacingDeferralMessage` is nil for `.transcribed` by design, so success-with-no-words was the only fully silent outcome.

**The prior session's lead was tested and discarded**, correctly: `ClipEditorCommitDecision.decide` returning `.skip` on an empty trimmed draft is the wipe guard and fires only when the *draft* is empty. Tom typed text; that guard was never on this path.
