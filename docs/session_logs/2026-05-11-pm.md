## Implemented

### Note editor as sheet
- New `Views/Components/NoteEditorSheet.swift` — mirrors `AudioPlayerSheet` shape minus player. Header timestamp, full-screen `TextEditor`, Cancel/Done toolbar, save-on-change semantics.
- `NoteEditorTarget` struct (mediaId, text, createdAt) added to `EntryExpandedView` for `sheet(item:)` presentation.

### Duplicate `.note` fragment fix
- **Bug**: opening detail view repeatedly minted new `.note` fragments. Old `migrateOrphanedContentIfNeeded` in `EntryExpandedView` only skipped on exact match between `entry.content` and a single note's text. After `regenerateContent` joined two notes ("A\n\nB"), the joined blob matched neither, so each open minted another. Next `regenerateContent` folded it back in → compounding.
- Logic extracted to `EntryLifecycleService.migrateOrphanedContentIfNeeded(entryId:)`. New guard: skip when any `.note` fragment exists on the entry — `entry.content` is presumed to be the joined output post-migration.
- Bug-first protocol followed: buggy code restored briefly to verify failing money test (`migrateOrphanedContentIfNeeded_skipsWhenAnyNoteFragmentExists`), then fix applied.
- Four tests covering: skip-when-any-note, repeated-calls-idempotent, legacy voice + orphan typed mints note, voice transcript covers content skips mint.

### Drag-to-scroll attempts
- `NotePanel.onTapGesture` + `simultaneousGesture(DragGesture)` was eating vertical drags on note panels.
- Attempt 1: `Button(.plain)` wrapping — didn't help.
- Attempt 2: UIKit-bridged `HorizontalSwipePanGesture` (`UIPanGestureRecognizer` subclass failing on vertical motion, delegate allowing simultaneous recognition). Broke pill `Button` tap-to-fire because UIView overlay claimed hit-testing across the panel frame; `.offset(x:)` on content didn't propagate hit-frame shift to the overlay UIView as expected.
- Reverted to SwiftUI `simultaneousGesture(DragGesture(minimumDistance: 8))`. Tap-to-edit dropped per user direction (swipe-edit is the only way in).
- Outcome: vertical-drag-from-text-on-detail-screen remains unfixed. Proper fix requires the swipe gesture attached to the panel's common parent UIView — a List refactor or full UIViewRepresentable wrapper around the panel. Deferred.

### "Delete empty memory?" prompt
- `EntryLifecycleService.isEntryEmpty(entryId:)` — returns true when entry has no media fragments.
- `EntryExpandedView.promptForPermanentDeleteIfEmpty()` called after every fragment-delete path (`applyEditsImmediately` for voice/photo/video; `deleteNoteFragment` for notes).
- Alert "Delete this memory?" — destructive Delete calls existing `lifecycle.delete(entryId:)` (hard delete, no recycle) and dismisses the detail view.
- Tests: `isEntryEmpty` (3 cases) + `delete_removesEntryFromStore`. UUID-bridge crash in `delete_removesEntryFromStore` fixed by snapshotting `entry.id` before deletion (deleted `NSManagedObject` crashes on `@NSManaged` access).

### URL detection at display time
- New `Views/Components/Linkify.swift` — `String.attributedWithLinks()` extension using `NSDataDetector(types: .link)` to build an `AttributedString` with `.link` runs on detected URLs.
- Applied at three render sites: `NotePanel.Text`, `VoiceClipPanel.Text`, `EntryExpandedView.bodyContent` plain-content fallback.
- No schema change; no transcriber change. Detection runs on each render; detection cost is negligible for short text.
- Catches `http(s)://`, bare domains, `mailto:`, `tel:`.
- Editor surfaces (`TextEditor` in `NoteEditorSheet` / `AudioPlayerSheet`) render plain — `TextEditor` doesn't honor attributed runs; links return on dismiss.
- 7 tests covering plain text, empty, https, bare domain, mailto, multiple URLs, character round-trip.
