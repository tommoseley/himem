## THE HEADLINE — a freeze that was never about cost, found only by instrument

Opening **Clips** locked the phone and did not recover. Four hypotheses were formed and **all four were wrong**. Each was reasoned off the diff and reported with more confidence than the evidence carried.

| # | Hypothesis | Killed by |
|---|---|---|
| 1 | Cost: `render()` recomputed 1 + ~4K times per frame, each dragging an NLTagger sweep | `[BenchPerf]`: render measured at **0.0–0.4ms**, 4 calls |
| 2 | Non-terminating loop in `ClipClusterProposer` | BFS terminates on `visited`; adjacency is O(n²) but bounded |
| 3 | Redundant publish feedback via `BenchAbsorbedMediaBus` | It has a change guard at `:36` |
| 4 | Ref-backed voice clips resolving to empty groups via a manifest-only map | Diagnostic returned vacuous (below) |

**Actual cause — an unstable identity.** `ClipGroup.id` was:

```swift
clips.first?.rollGroupId ?? clips.first?.clipId ?? UUID()
```

For an **empty** group that returns a **different value on every read**. `ForEach` re-reads identity, so SwiftUI can never match a row to its previous self and diffs forever. Fixed in `18021bc` with a stable sentinel; **the sentinel closed the freeze alone**, which is the proof.

**It predates 2b-ii** (present at `5fdd0a6^`), so it was fixed on its own merits rather than folded into the revert — otherwise the revert would have buried it. F6d's shape exactly.

### Why it never looked like itself

`[BenchPerf]` printed `render #1..#4 · 0.0–0.4ms · items=47`, then `body #1..#4`, then silence. No cost, no cycle, nothing to bisect — the churn was **entirely inside SwiftUI's diffing**. Three cost-shaped hypotheses died against that one measurement. Without the instrument the next round would have been a fourth.

**The instrument is the transferable lesson**, same as `[Amp]` (B10) and `[Meter]` (D10): three of this project's hardest defects were settled by a read-only log, not by reasoning.

## THE REVERT — `fa350d1`

Reverts `5fdd0a6` (2b-ii) and `9653e04` (its fix). **Tree verified byte-identical to `5fdd0a6^`**, not assumed.

**The deciding factor was not the freeze.** 2b-ii's headline claim was that "the number, the span and the session count cannot describe different sets, because there is only one set." On device:

- header **"7 new clips · 0 sessions"** with a card plainly on screen
- cluster subtitle **"1 clip from 1 sitting · 1 minute apart"** over **three rows spanning 58 minutes**
- expander **"Show all 1"**

`drawnCount` counted every drawn item; the session count read `render.loose.count`, which **excludes clustered sessions**. A proposal claiming every session leaves loose = 0. **Two sets, one line — the seventh instance of the class 2b-ii existed to end, three lines below a doc comment asserting it could no longer happen.** Patching would have left prose that lies about what the code guarantees: the phantom-comment class inside the commit written to close a different one.

### The row-resolution asymmetry (the finding that outlived the diff)

`clipsById` was built from `inbox.clips` alone while `benchItems` unioned manifest rows **and** refs. **Voice resolved through a manifest-only map; media resolved through `refsById`.** So photos survived and voice clips vanished from every count — which is what produced "1 clip" over three rows. On a mature bench nearly every clip is ref-backed (`materializeAll` drains transcribed rows into refs): this device reported **total=2 manifest clips against items=47**.

**Pre-2b-ii had no such asymmetry** — `composeBenchClips` synthesized rows from refs. The revert therefore *fixes* it, and the `resolve` patch was deliberately **not** carried forward: it had nothing to attach to. The finding survives as premise 2.

## THE REDO CONTRACT (ruled 2026-08-09/10)

1. **Every surface number derives from the DRAWN set**, clustered sessions included.
2. **Voice resolves from BOTH stores at EVERY site**, as media already does.
3. **No `ClipGroup` carries a content-independent id.** *(Closed in advance by `18021bc`.)*
4. **Guards assert on what the VIEW RENDERS, not on what `RenderedBench` computes.**

### Premise 4 is the one that decides whether the redo holds

The suite was **green at 1394/192 with both visible defects live**. `headerReadsTheLensSetNotTheRawBench` and the partition test passed **because they asserted on the composition, and the composition was correct**. Nothing asserted on what the view read out of it. Guard-the-caller, one layer further out than the three prior instances.

### The session-term ruling (Tom, 2026-08-09)

**Drop the session term when every session is clustered — count + span only.**

A header saying "1 session" over a cluster card **asserts the grouping the card is only proposing** — J5's observe-don't-conclude line crossed by the surface's own chrome rather than by the AI. *"1 group"* was rejected as well: it mints a noun the user has not accepted, and a second word for a sitting she would have to learn. When any session is loose the term returns and counts **all** drawn sessions. **The arithmetic is uniform; only the sentence is conditional.**

## THE ATOMICITY FINDING — why 2b-ii-c needs a fresh session by construction

**The header cannot move to `DrawnBench` alone.** The two paths group media by different rules:

| | Rule |
|---|---|
| `SessionMediaAbsorber` (cards, today) | media joins if `createdAt ∈ [earliest − 5min, latest + 5min]` of the session's **span**; no chaining |
| `UnifiedBenchGrouper` (`DrawnBench`) | item joins if the gap to the **adjacent item** is ≤ 10 min; **chains** |

2b-i recorded the shift deliberately. Wire the header to `DrawnBench` while the cards still use the absorber and the header counts a photo the cards draw elsewhere, or draw not at all — **reintroducing the exact class this rebuild exists to end, via a partial wiring.**

**There is no smaller honest increment: "one set" is the fix, so the set has to be one.** 2b-ii-c is therefore the full wiring — `BenchInventory → RenderedBench → DrawnBench`, header *and* cards, retiring the absorber: the ~678-line change in the file where all seven defects lived.
