## 4. Bench duration on a receive-only device — **resolved by honest absence; async derivation REJECTED (ruled 2026-07-30)**

**Type:** Honest-Label correctness. **Status:** decided.

`MediaReference` has no `duration` attribute, so a clip captured on one device and read on another has no entry in the per-device `BenchClipDurationStore`. `syntheticClip` must supply a value for the non-optional `InboxClip.duration` and supplied `0`, which the card rendered as a confident **"0:00"**. That is a duration the app states and that is false — the same Honest-Label class as an invented name, not graceful degradation. It is fully visible on a genuine multi-device user (iPhone + iPad + Watch).

**Ruled (Tom, 2026-07-30):**

1. **Now — honest absence.** Show *no* duration on a device that has not derived one. Absence is the honest state and **needs no announcement**: no marker, no placeholder, no chrome explaining an implementation detail the user never asked about. One-line guard at the adapter boundary; guarded by `ClipDisplayModelTests.voice_bench_unknownDuration_*` plus a `knownDuration_stillRenders` counter-test so a blanket suppression can't pass.

2. **Next deliberate schema batch — add `duration` to `MediaReference`.** The correct fix: cross-device, no downloads, additive attribute. Deferred only because a CloudKit schema change triggers the mandatory Production deploy ceremony, and P0-3 was explicitly sold as "no external deploy gate."

3. **~~Async `AVURLAsset.load(.duration)` derivation~~ — REJECTED and removed as the intended fix.** Deriving duration requires the audio bytes, which on a receive-only device sit **undownloaded** in the ubiquity container. Rendering the bench would therefore force-download every clip's audio — potentially a trip's worth over cellular — inverting the storage lock's download-on-demand posture. **It buys a duration string at the cost of bulk media transfer the user did not ask for.** Recorded as rejected rather than merely un-prioritised: *a bad plan left in a doc gets built eventually.*

**Note on where the defect came from.** The type system already modelled absence correctly in three places — `Evidence.audio(duration:)` is Optional, `ClipEvidenceProjection` renders nothing for a nil duration, and `BenchClipDurationStore.record` refuses non-positive values. A single `?? 0` coercion at the adapter boundary defeated all three. That is the F6a thesis exactly: **the invariant existed but had no owner, so a boundary coercion could overrule it.**
